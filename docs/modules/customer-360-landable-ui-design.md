# 客户 360 可落地 UI 方案

## 1. 设计目标

- 页面：客户 360
- 路由：`/customers/360`
- 实现文件：`src/views/customers/360/index.vue`
- 设计依据：`docs/modules/customer-360-optimization-detail.md`
- 本方案目标：给出一版能直接按现有项目实现的 UI，不采用三栏，不新增复杂数据模型，不引入新技术栈。

核心体验：

```text
找客户 -> 看状态 -> 看证据 -> 看历史 -> 做动作 -> 留痕验证
```

页面不做完整客户中台，也不做关系图、合同图表、渠道漏斗。首轮只把现有 `BusinessRecord` 数据用好，让页面能闭环。

## 2. 页面整体结构

推荐使用纵向工作流布局：

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 顶部操作条：说明 / 搜索 / 状态 / 查询 / 刷新 / 新建跟进                    │
├────────────────────────────────────────────────────────────────────────────┤
│ 客户切换条：横向记录胶囊，显示客户、风险、状态、负责人                    │
├────────────────────────────────────────────────────────────────────────────┤
│ 客户状态总览：客户名、标题、风险、状态、负责人、优先级、更新时间          │
├────────────────────────────────────────────────────────────────────────────┤
│ 风险与证据：风险说明、关键证据、AI 建议、验证口径                         │
├────────────────────────────────────────────────────────────────────────────┤
│ 互动与闭环时间线：当前记录 timeline                                       │
├────────────────────────────────────────────────────────────────────────────┤
│ 底部行动条：主动作 / 次动作 / 查看详情                                    │
└────────────────────────────────────────────────────────────────────────────┘
```

为什么这样设计：

- 用户阅读顺序和业务处理顺序一致。
- 不用三栏，避免信息被横向切开。
- 只依赖现有字段，能小范围改 `index.vue`。
- 动作区在底部承接时间线，闭环更自然。

## 4. 组件拆分建议

首轮不建议抽新组件。可以只在 `src/views/customers/360/index.vue` 内用语义化 class 拆结构。

| 区块 | 建议 class | 现有能力 | 是否新增组件 |
| --- | --- | --- | --- |
| 顶部操作条 | `biz-topbar` | 已存在 | 否 |
| 客户切换条 | `customer-switcher` | `records`、`active` | 否 |
| 客户切换项 | `customer-chip` | `BusinessRecord` | 否 |
| 状态总览 | `customer-summary` | `active` | 否 |
| 风险证据 | `customer-evidence` | `risk`、`description`、`tags`、`aiSuggestion` | 否 |
| 时间线 | `customer-timeline` | `active.timeline`、`a-timeline` | 否 |
| 底部行动条 | `customer-actionbar` | `changeStatus` | 否 |
| 详情抽屉 | 现有 `a-drawer` | 已存在 | 否 |

这样做的好处是页面可读、改动集中，也不会为一个小页面提前抽象。

## 5. 数据映射

完全复用 `BusinessRecord`。

| UI 内容 | 字段 |
| --- | --- |
| 客户名 | `record.customer` |
| 记录标题 | `record.title` |
| 编号 | `record.code` |
| 负责人 | `record.owner` |
| 状态 | `record.status` |
| 优先级 | `record.priority` |
| 风险 | `record.risk` |
| 说明 | `record.description` |
| AI 建议 | `record.aiSuggestion` |
| 标签 | `record.tags` |
| 更新时间 | `record.updateTime` |
| 时间线 | `record.timeline` |

不建议首轮新增字段：

- 合同金额。
- 续约日期。
- 客户等级枚举。
- 情绪分。
- 渠道触点类型。
- 订单列表。

如果要展示“高价值”“续约临近”这类内容，首轮只放在文案或标签里，不新增模型。

## 6. 交互细节

### 6.1 默认加载

- 页面加载后调用 `loadData`。
- `records` 有数据时默认选中第一条。
- `records` 为空时展示空状态，不展示假的客户摘要。

### 6.2 客户切换

- 点击客户切换项：
  - 设置 `active = record`。
  - 不打开抽屉。
  - 状态总览、风险证据、时间线、底部行动同步变化。
- 当前选中项：
  - 边框使用 `var(--app-primary)`。
  - 左侧或顶部加一条主色强调线。

### 6.3 查看详情

- 点击“查看详情”：
  - `detailRecord = active`。
  - `detailOpen = true`。
- 抽屉沿用现有内容。
- 抽屉不承担主要工作流，只补充完整记录。

### 6.4 状态动作

主动作按状态变化：

| 当前状态 | 主动作 | 调用 |
| --- | --- | --- |
| 待处理 | 安排回访 | `changeStatus(active, '处理中')` |
| 处理中 | 提交审核 | `changeStatus(active, '待审核')` |
| 待审核 | 标记完成 | `changeStatus(active, '已完成')` |
| 已完成 | 查看闭环 | 打开详情 |
| 已暂停 | 恢复处理 | `changeStatus(active, '处理中')` |
| 已关闭 | 查看闭环 | 打开详情 |

底部行动条只展示一个主按钮，避免复杂操作区。

## 7. 视觉规范

遵循当前项目深色企业工作台风格。

| 项 | 建议 |
| --- | --- |
| 页面背景 | 沿用 `var(--app-bg)` |
| 面板背景 | `var(--app-surface)` |
| 弱面板背景 | `var(--app-surface-muted)` |
| 边框 | `var(--app-border)` |
| 主色 | `var(--app-primary)` |
| 圆角 | 8px |
| 页面间距 | 16px |
| 面板内边距 | 14px 到 16px |
| 阴影 | 复用当前 `0 10px 26px rgba(15,23,42,.06)`，不要加重 |

颜色语义：

| 类型 | 颜色 |
| --- | --- |
| 主动作/选中 | `var(--app-primary)` |
| AI/建议 | `var(--app-accent)` 或项目现有强调色 |
| 风险高 | Ant Design `red` tag |
| 风险中 | Ant Design `orange` tag |
| 风险低 | Ant Design `green` tag |
| 已完成 | Ant Design `success` tag |

窄屏策略：

- 1360px 以下仍保持纵向布局。
- 客户切换条允许横向滚动。
- 底部行动条按钮不换成多列，不堆很多按钮。

## 9. 页面状态

### 加载态

- 顶部操作条保留。
- 客户切换条展示 3 个骨架块。
- 状态总览、风险证据、时间线展示简单骨架。
- 不出现空白大面板。

### 空状态

文案：

```text
暂无客户跟进记录
```

操作：

- 显示“新建跟进”按钮。
- 不显示底部行动条。

### 错误态

如果 `loadData` 失败：

- 顶部 message 提示加载失败。
- 保留“刷新”按钮。
- 不清空用户已输入筛选条件。

### 无选中记录

文案：

```text
请选择一条客户记录
```

触发场景：

- 列表为空。
- 筛选后无结果。

## 10. 可实现模板

后续改代码时，模板结构可以控制在下面这种复杂度：

```vue
<template>
  <div class="biz-page biz-page--customer">
    <header class="biz-topbar">...</header>

    <section class="customer-switcher">...</section>

    <section v-if="active" class="customer-summary">...</section>

    <section v-if="active" class="customer-evidence">...</section>

    <section v-if="active" class="customer-timeline">...</section>

    <section v-if="active" class="customer-actionbar">...</section>

    <a-empty v-else description="暂无客户跟进记录" />

    <a-drawer>...</a-drawer>
    <a-modal>...</a-modal>
  </div>
</template>
```

脚本只需要新增少量方法：

```ts
function selectRecord(record: BusinessRecord) {
  active.value = record;
}

function openDetail(record = active.value) {
  if (!record) return;
  detailRecord.value = record;
  detailOpen.value = true;
}
```

可以新增一个轻量计算方法，但不要抽复杂配置：

```ts
function nextAction(record: BusinessRecord | undefined) {
  if (!record) return undefined;
  if (record.status === '待处理') return { label: '安排回访', status: '处理中' as const };
  if (record.status === '处理中') return { label: '提交审核', status: '待审核' as const };
  if (record.status === '待审核') return { label: '标记完成', status: '已完成' as const };
  if (record.status === '已暂停') return { label: '恢复处理', status: '处理中' as const };
  return undefined;
}
```

## 11. 验收清单

- 不采用三栏布局。
- 默认能看到当前客户是谁。
- 点击客户切换条后，状态总览、风险证据、时间线、行动条同步变化。
- AI 建议不孤立展示，必须和风险证据放在同一业务上下文里。
- 底部只有一个主动作，动作后状态推进并刷新时间线。
- 详情抽屉可打开，展示完整闭环记录。
- 空数据、加载中都有可理解状态。
- 首轮只改 `src/views/customers/360/index.vue` 即可实现。

## 12. 结论

这版 UI 的关键不是“更炫”，而是把客户 360 做成一个可操作的纵向处理台：

```text
客户切换条定对象，状态总览定判断，风险证据定原因，时间线定过程，底部行动定闭环。
```

它可以在现有代码和数据结构上落地，复杂度可控，后续再接真实客户、合同、订单、触点数据时也有自然扩展位置。
